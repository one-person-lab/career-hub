# **Kafka 如何保证消息不丢失？**

### **1\.** **生产阶段：确保消息成功写入 Kafka**

**生产者配置**：

-   acks **参数**：

-   acks=0：生产者发送消息后不等待确认，可能导致消息丢失。
-   acks=1：等待 Leader 确认，Leader 崩溃可能丢失消息。
-   acks=all：等待所有 ISR（同步副本集合）确认，最可靠，但有性能开销。

**重试机制**：

-   retries：配置重试次数，确保发送失败时自动重试。
-   delivery.timeout.ms：设置消息的最长发送时间。

**幂等性**：

-   enable.idempotence=true：开启幂等性，确保即使生产者重试，同一条消息也只会被写入一次。

* * *

### **2\.** **存储阶段：确保消息安全存储在 Kafka**

**副本机制**：

-   ISR（In-Sync Replicas）：Kafka 通过 ISR 机制确保消息在多个副本中存储。

-   只有当消息成功写入所有 ISR 副本后，才会被确认。

**日志持久化**：

-   Kafka 会将消息写入磁盘日志文件，通过顺序写操作提高写入效率。
-   log.flush.interval.messages 和 **log.flush.interval.ms**：控制日志刷盘频率。

**Broker 容错**：

-   副本机制允许 Broker 故障时，其他副本接管，防止数据丢失。

* * *

### **3\.** **消费阶段：确保消息可靠消费**

**消费者确认机制**：

-   手动提交偏移量：通过消费者手动提交偏移量，确保消息被处理后才标记为已消费。
-   使用 **enable.auto.commit=false** 和 **commitSync()**，确保消费确认是显式的。

**重复消费防护**：

-   消费者端实现幂等性，避免重复消费导致数据污染。

* * *

### **4\.** **系统容错：应对网络故障或意外宕机**

**数据冗余**：

-   Kafka 的分区副本机制允许数据在多个 Broker 上存储，副本数越多，数据丢失概率越低。

**优先副本机制**：

-   Kafka 确保 Leader 副本始终是 ISR 中的一部分，防止 Leader 丢失导致数据不一致。

**磁盘配置**：

-   Kafka 推荐使用 RAID 或磁盘阵列以增加存储的可靠性。

* * *

* * *

### **6\.** **总结**

Kafka 通过生产者幂等性、存储副本机制、消费者确认机制等手段全面保证了消息不丢失。

同时，需要根据业务需求在性能和可靠性之间进行权衡。例如：

-   高可靠性：acks=all + 高副本数。
-   高性能：acks=1 + 低副本数。

**面试建议**：结合实际场景，比如流量削峰、金融交易等，用自己的项目经验说明如何利用 Kafka 确保消息不丢失。

# **Kafka为什么支持大数据量级？**

#### **(1) 高吞吐量**

-   Kafka 利用 **顺序写入磁盘** 和 **零拷贝技术**，大幅提升了数据写入和读取的效率，性能接近内存级别。
-   支持 **批量处理** 和 **消息压缩**，可以有效减少网络和存储开销。

#### **(2) 分布式架构**

-   Kafka 通过 **分区（Partition）** 将主题（Topic）拆分成多个分区，每个分区可以分布到不同的 Broker 节点上。
-   这种分区机制使 Kafka 能够利用集群中多个服务器的存储和计算能力，实现水平扩展，适应大数据量场景。

#### **(3) 可靠的存储机制**

-   Kafka 的日志采用 **分段存储**，每个分区的日志文件可以独立管理，大量历史数据不会影响当前写入和读取性能。
-   提供可配置的持久化策略，可以选择基于时间或大小来清理数据，适合日志和审计场景。
-   副本机制 确保数据不会因为单节点故障而丢失。

#### **(4) 高扩展性**

-   Kafka 支持动态增加分区和 Broker，扩展时对现有服务影响较小。
-   消费者组允许多个消费者并行消费，提升数据处理能力。

#### **(5) 灵活的数据消费方式**

-   消费者可以通过偏移量精确定位消息，实现重复消费或从某个时间点重新消费。

#### **(6) 支持大数据生态**

-   Kafka 能无缝集成到 Flink、Spark、Hadoop 等大数据框架中，形成完整的数据处理链路。

## **零拷贝**

零拷贝是指计算机执行 I0 操作时，CPU 不需要将数据从一个存储区域复制到另一个存储区域，从而可以减少上下文切换以及 CPU 的拷贝时间。它是一种 I/0 操作优化技术。
