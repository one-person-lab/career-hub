# 认证授权

# **认证**

Authentication

证明你是你自己，就是登录（账号密码、短信验证码、邮件链接）

# **授权**

Authorization

授权第三方应用访问该用户某些资源的权限

# **令牌**

-   JWT (JSON Web Token)

JWT本身是一种令牌格式，适合分布式系统，不需要额外存储和查找用户信息。

-   Access Token（访问令牌）

访问资源接口（API）时所需要的资源凭证

-   Bearer Token（持有者令牌）

Bearer Token是一种访问令牌，任何持有该 Token 的人都可以访问相应资源。

-   Custom Token（自定义令牌）

自定义 Token 是应用自己设计的 Token，包含特定的信息和加密方式，适用于特殊的业务场景和独立系统，缺乏标准化支持。

# **请求上下文**

-   HttpServletRequest的Attribute

request.setAttribute只适合在视图层传递，如果跨层就需要通过方法参数传递，导致代码冗余

-   ThreadLocal

可以跨层传递，同一线程内的任意方法都能访问，正常是在拦截器或过滤器设置用户信息并传递到业务层

### **1\.** **ThreadLocal**

#### **工作原理**

-   ThreadLocal 提供了每个线程独享的一份数据拷贝，各线程之间的数据是独立的。
-   数据是绑定在线程对象的 ThreadLocalMap 上，生命周期与线程一致。

#### **特点**

-   线程隔离：每个线程访问的都是自己的数据。
-   使用场景：适用于在线程中保存与线程相关的上下文信息，例如数据库连接、用户会话等。

#### **局限性**

-   在使用线程池时，线程可能被复用，ThreadLocal 的数据不会自动清除，可能导致**脏数据**问题。
-   ThreadLocal 的数据不能在父线程和子线程之间传递。

### **2\.** **TransmittableThreadLocal**

#### **工作原理**

TransmittableThreadLocal 是阿里巴巴开源的扩展，解决了 ThreadLocal 的一些局限性，特别是在 **线程池复用** 和 **父子线程数据传递** 方面。

-   在线程池中，可以确保线程复用时，数据上下文能够正确传递。
-   支持在父线程和子线程之间传递 ThreadLocal 数据。

#### **核心机制**

-   在任务提交到线程池时，TransmittableThreadLocal 会对上下文数据进行备份。
-   任务执行前将备份数据复制到工作线程的 ThreadLocal 中，任务执行后恢复原有上下文。

#### **特点**

-   数据传递：支持父线程到子线程的数据传递。
-   线程池支持：解决线程池复用引起的脏数据问题。
-   开销更大：由于需要备份和恢复上下文，性能稍低于 ThreadLocal。

#### **使用场景**

-   需要在线程池中传递上下文数据时，如分布式追踪的 TraceID、用户上下文、事务上下文等。
-   父线程创建的线程任务需要共享上下文数据。

#### **ThreadLocal 示例**

ThreadLocal<String> threadLocal = new ThreadLocal<>(); threadLocal.set("Main Thread Data"); new Thread(() -> { System.out.println("Thread Data: " + threadLocal.get()); // 输出 null }).start();

#### **TransmittableThreadLocal 示例**

import com.alibaba.ttl.TransmittableThreadLocal; TransmittableThreadLocal<String> transmittableThreadLocal = new TransmittableThreadLocal<>(); transmittableThreadLocal.set("Main Thread Data"); // 子线程能够访问父线程的上下文数据 new Thread(() -> { System.out.println("Thread Data: " + transmittableThreadLocal.get()); // 输出 "Main Thread Data" }).start();

#### **线程池场景下的对比**

-   ThreadLocal 的上下文数据不会随线程池任务切换而正确传递，可能出现脏数据。
-   TransmittableThreadLocal 在任务提交时自动传递上下文数据，确保线程池环境中数据一致性。
