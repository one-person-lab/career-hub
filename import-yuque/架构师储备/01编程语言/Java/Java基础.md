## **1.1 HashMap的底层原理？**

HashMap存放键值对，存储在哈希表的数据结构中，通过计算key的hashCode的值来确定键值对在数组中的位置，加入产生碰撞则使用链表或者红黑树。为了避免碰撞，HashMap将数组的长度始终保持为2的次幂，将哈希值的高位参与运算，通过位与操作来等价取模操作。

JDK1.7中，HashMap的底层使用的是数组+链表的结构，JDK1.8之后，使用的是数组+链表|红黑树。1.7链表是头插法，可能导致死循环。

之所以将key值转为hash再二次hash（原始hash值异或运算原始hash值右移16位，相当于是取高位，这样做的目的是将高位的信息混合到低位中，更好的分散键的hash码）再跟集合容量取模获取桶下标，是为了快速查找和解决hash冲突使数据散列分布。

之所以1.8加上红黑树，是为了解决链表超长的问题，预防DoS攻击，因为链表的查询效率低，时间复杂度为n，红黑树的查询效率为log n，当链表的长度超过8并且数组容量大于64时，则将链表转换为红黑树，之所以超过8才转成树，是因为hash冲突发生8次的概率仅为亿分之六，当链表长度小于6，又会转为链表

之所以数据超过容量四分之三才扩容，是因为太早扩容会造成空间浪费，太晚扩容会造成检索变慢。

之所以扩容的大小是2的n次幂，首先是可以使用按位与运算代替取模求桶下标，提高计算效率，其次在计算新的桶下标时，hash值按位与旧容量为0时则留在原来位置，不为0则新位置=旧位置+旧容量。

线程不安全，比如当两个线程同时取到hash桶的位置，就会导致有一个线程的数据丢失。HashTable是在HashMap的基础上在方法里加锁达到线程安全，性能差，已经被淘汰。

HashMap是懒惰加载，在创建对象时并没有初始化数组

## **1.2 JDK动态代理机制？**

它是Java提供的一种代理技术，在运行时动态生成某个接口的代理类，并可以在代理类中实现自定义逻辑处理。

当我们要访问目标类时，通过代理类来访问目标类完成操作。这样做的好处是可以在调用目标类之前和之后去添加一些预处理和后处理的操作，来扩展一些不属于目标类的功能。比如说可以方法执行开始和结束前记录日志，在方法执行前进行参数校验，进行事务管理、权限校验等等。

静态代理，就是在程序运行之前我们就给目标类编写了其代理类的代码，然后编译了其代理类，就是在程序运行之前已经生成了它代理类的字节码文件。

动态代理，就不需要实现给目标类去编写代理代码，而是在运行中通过反射自动生成代理对象，比如我们使用JDK动态代理，只需要我们代理类去实现InvocationHandler，然后去实现invoke方法，就可以代理任何你想控制访问的类，最核心的就是通过Proxy.newProxyInstance()去生成动态代理类以及访问它的实例。

JDK动态代理需要基于接口才能代理，它是标准的Java SE API，无需依赖额外jar包。Cglib是通过继承来生成代理类，并且需要引入额外jar包。JDK动态代理作为标准Java SE能满足Spring AOP的需求，所以成为了默认选择，必要时才会开启CGLIB代理。

#### **项目中有没有用过设计模式，聊聊应用场景？**

嗯，有的，比如说在之前的示例项目B中，做支付服务，需要聚合多种支付方式，需要提供统一的支付接口给App。这时候就用到了策略模式+工厂模式来提高可扩展性和灵活性。策略模式用来处理不通支付方式的选择和执行，每种支付方式看作是一个策略，创建一个支付策略的接口，每种支付方式实现具体的策略类，最后客户端根据需要选择合适的策略进行支付。工厂模式用来创建不通的支付对象，比如微信、支付宝、银行卡，创建一个支付工厂接口，每种支付方式实现具体的支付工厂类，这样就可以实现对象的创建和使用分离，使代码更具扩展性。

总之，这两种模式的结合在实际场景中很常用，适用于任何根据不同情况来选择不同实现的场景，可以很方便后续的扩展，比如新增一种策略。

#### **hashcode和equals？**

equals相等hashcode一定相等

hashcode相等equals不一定相等

因为equals默认比较的是内存地址，hashcode默认的生成规则是根据hash函数来的。

如果重写了hashcode方法，生成规则就是根据成员变量的内容生成，成员变量内容一样，hashcode就一样，但是hashcode一样，成员变量内容不一定一样。

如果重新了equals方法，先对比内存地址，不匹配则对比成员变量的内容。

#### **数组数据结构？**

数组是一种用连续的内存空间存储相同数据类型数据的线性数据结构

int\[\] array = {1, 2, 3, 4, 5};

寻址公式：array\[i\] = baseAddress + (i \*dataTypeSize); 数组的首地址+元素类型的大小，int类型就是4个字节

为什么数组索引从0开始呢？假如从1开始不行吗，对于CPU来说，如果从1开始，增加了一个减法指令

操作数组的时间复杂度（查询）？根据索引查询时间复杂度就是 O(1)，未知索引查询O(n)，如果是有序的通过二分查找就是O(logn)

操作数组的时间复杂度（插入、删除）？数组是一段连续的内存空间，因此为了保证数组的连续性会使得插入和删除效率变得很低，最好情况是O(1)，最坏情况是O(n)，所以是O(n)。

#### **链表数据结构？**

-   单向链表

-   链表中的每个元素称之为结点（Node），每个结点分为两部分，一个是存储数据元素的数据域，一个是存储下一个结点地址的指针域
-   物理存储单元上，非连续、非顺序的存储结构
-   查询时间复杂度O(n)，需要遍历链表，查询头是O(1)，插入删除时间复杂度O(n)，查找时需要遍历链表

-   双向链表

-   双向链表需要额外的两个空间来存储后继结点和前驱结点的地址
-   支持双向遍历，双向链表操作的灵活性
-   查询时间复杂度O(n)，需要遍历链表，查询头尾是O(1)，插入删除时间复杂度O(n)，查找时需要遍历链表，给定结点是O(1)，

#### **Error和Exception的区别？**

Error是虚拟机和系统级别的问题，比如说内存溢出、虚拟机崩溃。Exception也分为检查型异常和非检查型异常，检查型异常需要在代码层面强制处理，要么捕获要么抛出，非检查型异常也称为运行时异常，如空指针异常。
