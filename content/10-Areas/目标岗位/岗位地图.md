# 岗位地图

> 一句话：一个目标岗位一篇 —— 它要什么、我有什么、差在哪。

## 从缺口倒推，而不是从能力正推

常见的错误是「我会什么 → 那我就投什么」。正确的方向是反过来的：

**这个岗位要什么 → 我有哪些项目能对上 → 哪一条对不上 → 那条要不要补。**

因为对不上的地方，面试官一定会问。

## 一篇岗位画像写什么

| 段落 | 内容 |
|------|------|
| 岗位画像 | JD 里的硬性要求和真正的考察点（两者常常不一样） |
| 匹配矩阵 | 一条要求一行：`要求` / `我拿什么讲（项目名）` / `覆盖度` / `备注` |
| 缺口 | 对不上的项，以及打算怎么补（补不了就诚实标注） |
| 这个岗位的叙事主线 | 一句话：为什么是我 |
| 高频问题 | 针对这个岗位最可能被问的 5–10 个问题 |

## 覆盖度怎么算

| 标记 | 含义 |
|------|------|
| 覆盖 | 有直接项目（能翻到数字） |
| 部分 | 有相关经历，但不是同一个量级/场景 |
| 缺 | 没有对应项目，只能靠迁移推理 |

**「缺」不要藏着。** 藏着它会在面试现场暴露，写下来反而能提前想好怎么答。

## 怎么加一篇

复制本文件结构和下面的模板段，命名成 `<岗位名>.md`。一个岗位一个文件，不要混在一篇里 —— 混了就没法算覆盖度。
