# AI Agent

角色 目标 工具 规则 格式

# 面试官：你们无人机平台是怎么做 AI Agent 的？

你可以这样回答：

## 第一层：为什么做

我们当时考虑AI Agent，主要不是为了增加一个聊天功能，而是希望解决无人机平台操作门槛比较高的问题。

传统无人机平台里，用户如果想完成一次巡检任务，需要自己选择设备、规划航线、设置任务参数，再启动任务，专业性比较强。

所以我们的思路是把原来的**“用户操作系统”**转变成**“用户描述任务，系统帮助执行任务”**。

比如用户可以描述：

**“对这个区域进行一次巡检，如果发现异常目标就悬停并拍照。”**

系统首先理解用户的目标，然后把它转换成具体的无人机任务。

* * *

# 第二层：怎么实现

这里是你最需要记住的部分。

### ① 用户 → 大模型

首先用户通过文本或者语音描述任务。

大模型主要负责的是**自然语言理解和任务规划**，而不是直接控制无人机。

比如用户说“沿着这条路巡检，发现异常就拍照”，模型需要理解里面包含几个任务：

**路线巡检、异常检测、悬停、拍照。**

### ② 大模型 → Agent任务规划

接下来进入Agent层。

Agent会把用户的自然语言转换成结构化任务。

比如类似：

```
任务：道路巡检
区域：当前选定区域
触发条件：发现异常目标
动作：悬停 + 拍照
```

然后Agent根据任务决定需要调用哪些工具。

### ③ Agent → Tools

我们不会让大模型直接调用无人机底层接口，而是把无人机能力封装成标准工具。

比如：

```
createMission()
startMission()
pauseMission()
getDeviceStatus()
takePhoto()
getLiveStream()
```

大模型实际上调用的是这些业务工具。

工具层再去调用下面真正的无人机控制接口。

这就是你一定要理解的：

**LLM不是飞控。**

**LLM负责理解和规划，Tool负责调用能力，业务系统负责控制，设备负责执行。**

* * *

# 第三层：真正的难点

这一层是你面试最容易体现“架构思维”的地方。

### ① AI不能直接控制无人机

无人机属于真实物理设备，所以我们不能让大模型生成一个指令以后直接发送给无人机。

中间必须有业务控制层。

比如AI说：

“飞到这个位置。”

我们的业务系统需要先检查：

**坐标是否合法、飞行高度是否合法、设备当前是不是可执行状态、有没有权限、是不是处于禁飞或者限制区域。**

所以真正执行之前要经过一层安全校验。

这一点其实也是目前公开的 FlightHub 2 Copilot 产品强调的设计：AI动作需要人工确认，并且用户可以随时暂停。

### ② 实时控制不能全部交给大模型

第二个问题是实时性。

我不会让大模型参与所有实时控制。

比如无人机的姿态控制、避障、基础飞控，这些本身就应该由确定性的飞控和设备系统负责。

AI更适合做的是**高层任务理解和决策**。

所以可以理解成：

**AI决定“我要完成什么”，设备系统负责“具体怎么飞”。**

### ③ AI识别和任务执行要解耦

第三个问题是AI识别。

比如无人机巡检过程中，视频流可以进入视觉识别能力，识别到指定目标以后产生一个结构化事件。

比如：

```
event = abnormal_target_detected
location = xxx
confidence = 0.92
```

然后由业务规则决定是不是触发悬停、拍照、告警等动作。

这样就不会让大模型直接根据一帧图片决定无人机怎么飞。

这个思路和 FlightHub 2 当前公开的能力也比较接近：它支持在航线执行过程中进行多模态目标识别，识别触发后进行通知，并支持自动化任务。

# 第四层：最终形成什么架构

你如果被问：

**“那你整个Agent架构怎么设计？”**

你直接说：

我会把它分成五层。

**第一层是交互层**，负责文本、语音等自然语言输入。

**第二层是Agent层**，负责意图识别、任务拆解和任务编排。

**第三层是Tool工具层**，把无人机能力标准化，比如创建任务、启动任务、暂停任务、拍照、获取设备状态等。

**第四层是业务控制层**，负责权限、安全规则、参数校验、任务状态和人工确认。

**第五层是设备接入层**，负责对接无人机厂商SDK、云平台或者设备协议。

这样做最大的好处是**AI和设备解耦**。

以后即使换大模型，下面的无人机业务不用跟着改；如果增加新的无人机厂商，也可以主要在设备接入层进行适配。

* * *

# 第五层：举一个完整例子

这个你下午最好直接背下来，因为它能把前面的技术全部串起来。

比如用户说：

**“帮我对这个区域进行巡检，如果发现异常目标就停下来拍照。”**

首先，用户请求进入Agent。

Agent理解以后，把任务拆成“区域巡检、异常检测、悬停、拍照”几个动作。

然后Agent调用我们定义好的任务工具创建巡检任务。

业务控制层会校验用户权限、设备状态、任务参数以及飞行安全条件。

校验通过以后，任务下发到设备。

无人机执行过程中，视频流进入AI识别模块，如果识别到目标，就产生一个结构化的异常事件。

业务系统根据这个事件判断是否触发悬停和拍照。

最后把执行结果、异常位置、图片和任务状态返回给用户。

所以整个链路就是：

**自然语言 → Agent理解 → 任务规划 → Tool调用 → 安全校验 → 无人机执行 → AI识别 → 事件触发 → 结果反馈。**

# 如果面试官问：这个和普通AI聊天有什么区别？

你直接回答：

我认为最大的区别就是**AI有没有真正进入业务闭环**。

普通AI聊天是：

**用户提问 → AI回答。**

我们这个场景是：

**用户提出目标 → AI理解目标 → AI规划任务 → 调用业务能力 → 真实设备执行 → 获取实时结果 → 再反馈给用户。**

所以AI在这里不是一个聊天入口，而是成为了业务流程中的一个智能决策和任务编排层。
