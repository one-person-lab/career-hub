# 面试问答

> 一句话：同一批成果，按不同场合组装成不同的说法。这里不生产内容，只做组装。

## 四份材料，一个来源

| 材料 | 面向 | 长度 | 从哪来 |
|------|------|------|--------|
| 简历版本 | 陌生人（HR / 招聘方） | 1–2 页 | 从项目成果挑 3–5 张卡，按岗位重排 |
| 自我介绍 | 面试官 | 1 / 3 / 5 分钟三版 | 挑 1 张卡当主线，其余做支撑 |
| 故事库 | 行为面 | 单条 2 分钟 | 项目成果里勾了「行为面」的卡，按 STAR 展开 |
| 作品集 | 愿意深看的人 | 无上限 | 成果卡的技术细节 + 架构图 |

**共同来源都是 `content/项目成果/`。** 所以改一条卡，四处同时更新 —— 这就是这个工作台存在的理由。

## 故事库要覆盖哪些题型

行为面的题库是有限的，别一篇篇准备，按题型准备。经典八类：

| 题型 | 考察什么 |
|------|---------|
| 主导的项目 | 能不能扛事 |
| 从 0 到 1 | 在模糊里做判断 |
| 失败与复盘 | 是不是把失败变成了资产 |
| 技术分歧 | 怎么处理「我对你错」 |
| 冲突处理 | 人际而非技术 |
| 项目延期 | 怎么管预期 |
| 推动他人 / 跨团队 | 没有权限时怎么成事 |
| 超出职责的事 | 主动性 |

每个题型配 1–2 个故事，一共 8–12 个就够覆盖绝大多数面试。

## 简历版本怎么管理

- 一个岗位方向一份，不要每家都从零写
- 每份标注**用了哪些成果卡**，改卡时能知道哪些简历要跟着改
- 投出去之后留一份快照，否则面试时你都不记得当初发的是哪版

## 自我介绍的三版

| 版本 | 用途 | 结构 |
|------|------|------|
| 1 分钟 | 电梯 / 电话初筛 | 定位 + 1 条最强证据 + 为什么是这 |
| 3 分钟 | 面试标准开场 | 定位 + 2 条证据 + 目标 |
| 5 分钟 | 需要完整铺开时 | 加一条完整项目叙事 |
